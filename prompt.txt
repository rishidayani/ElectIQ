## 🎯 PROJECT OVERVIEW

Build a full-stack **Election Intelligence Platform** — a web application that ingests raw election-related data (vote counts, candidate profiles, constituency results, turnout figures, historical trends) and transforms it into clean, intuitive, real-time visual insights for voters, journalists, researchers, and election monitors.

The product must feel like a **mission control dashboard** — authoritative, data-dense, but deeply readable. Think Bloomberg Terminal meets Nate Silver's 538 — but accessible to a first-time voter.

## 🗂️ APPLICATION ARCHITECTURE

### Pages / Screens

#### 1. **Live Results Dashboard** (Home / Default View)
- Full-width hero: "Election Night" mode — seat/vote tallies update in real-time
- Party seat distribution — horizontal stacked progress bar (the "magic number" bar)
- Top-5 trending constituencies — live updating leaderboard
- National vote share donut chart (center-labeled with leading party)
- Turnout meter (gauge chart, 0–100%) — national and state-wise
- Alerts ticker (bottom fixed bar): "Counting complete in X", "Seat flipped to Y"

#### 2. **Constituency Explorer**
- Searchable, filterable map (SVG or Leaflet.js choropleth)
- Click on any constituency → side panel slides in showing:
  - Candidate breakdown table (votes, %, change from last election)
  - Historical results (mini bar chart: last 3 elections)
  - Demographics snapshot (population, registered voters, turnout)
  - Margin of victory indicator (visual spread bar)
- Filter by: State, Party, Margin Size, Status (declared/pending)

#### 3. **Candidate Profiles**
- Search by name or party
- Card grid: candidate photo placeholder, name, party badge, constituency
- Detail view: vote history, vote share over elections, social sentiment tag (positive/neutral/negative from uploaded data)
- Compare mode: side-by-side comparison of up to 3 candidates

#### 4. **Party Intelligence**
- Party-level aggregated stats: total seats, swing seats, total votes
- Seat projection chart: current vs. projected (horizontal diverging bar)
- Performance heatmap by region/state
- Alliance mapping: which parties are in coalition

#### 5. **Historical Trends**
- Line chart: vote share by party over last 5 elections
- Swing analysis: which constituencies switched party over time
- Voter turnout trend (line chart, year-over-year)
- "Swing-o-meter" widget: interactive dial showing seat swing

#### 6. **Data Upload & Ingestion Panel** (Admin/Analyst View)
- Drag-and-drop CSV/JSON upload
- Column mapping wizard (map "Constituency Name" → canonical field)
- Data validation report (errors, warnings, missing fields)
- Preview table before confirming import
- Upload history log

#### 7. **Alerts & Monitoring Center**
- Rule builder: "Alert me when turnout in X drops below 40%"
- Alert history feed (timestamp, type, severity)
- Export alerts as CSV/PDF

#### 8. **Settings & Configuration**
- Toggle: Dark / Light / System mode
- Election configuration: set election name, date, total seats
- Party management: add/edit/remove parties with colors and logos
- Data source management: API endpoints or file uploads

## ⚙️ BACKEND ARCHITECTURE

### Core Services

#### 1. Data Ingestion Service
- Accept CSV, JSON, XLSX uploads via REST API
- Parse, validate, normalize data into canonical schema
- Idempotent upsert: reprocessing same data doesn't duplicate records
- Emit ingestion events to message queue (Kafka/Redis)

#### 2. Election Data API (REST + WebSocket)
- `GET /api/elections` — list elections
- `GET /api/elections/:id/results` — aggregated results
- `GET /api/constituencies` — list with filters
- `GET /api/constituencies/:id` — detailed result
- `GET /api/parties` — all parties with stats
- `GET /api/candidates` — searchable candidate list
- `GET /api/trends` — historical time-series data
- `GET /api/alerts` — alert history
- `POST /api/alerts/rules` — create alert rule
- `POST /api/upload` — ingest data file
- `WS /ws/live` — WebSocket channel: push real-time result updates

#### 3. Computation Engine
- Runs after each data ingest: recalculates totals, percentages, swings, projections
- Seat projection model: configurable (FPTP, PR, etc.)
- Generates pre-aggregated summary snapshots stored in cache

#### 4. Alert Engine
- Polling or event-driven: checks alert rules after each computation
- Sends notifications via: in-app feed, email (SMTP), webhook
- Alert types: seat flip, margin below threshold, turnout drop, counting complete

#### 5. Auth Service
- Public read access (viewer role)
- Authenticated upload/admin (analyst role)
- JWT-based auth, refresh tokens
- Optional: OAuth2 (Google sign-in for analyst access)

### Database Schema (Core Tables)

```sql
elections         — id, name, date, total_seats, status, config
constituencies    — id, election_id, name, state, registered_voters
candidates        — id, name, party_id, constituency_id, photo_url
parties           — id, name, abbreviation, color_hex, alliance_id
results           — id, candidate_id, constituency_id, votes, status, updated_at
turnout           — id, constituency_id, registered, voted, percentage, updated_at
historical_results— id, constituency_id, election_year, candidate_name, party_id, votes
alert_rules       — id, user_id, condition_type, threshold, target_id, active
alert_history     — id, rule_id, triggered_at, message, severity
uploads           — id, filename, uploaded_by, status, rows_processed, errors
```

## 🔄 DATA FLOW

```
[CSV/JSON Upload]
       ↓
[Ingestion Service] → validate → normalize → upsert to DB
       ↓
[Message Queue] → triggers Computation Engine
       ↓
[Computation Engine] → recalculate aggregates → store in Cache (Redis)
       ↓
[Alert Engine] → evaluate rules → fire alerts
       ↓
[WebSocket Server] → push updates to connected clients
       ↓
[Frontend Dashboard] → live data refresh (no page reload)
```

## 🛡️ NON-FUNCTIONAL REQUIREMENTS

- **Real-time updates**: WebSocket or Server-Sent Events — dashboard refreshes without page reload
- **Performance**: Dashboard initial load < 2 seconds; chart render < 500ms
- **Accessibility**: WCAG 2.1 AA — keyboard nav, ARIA labels, color-blind-safe palette
- **Responsiveness**: Mobile-first layout; full dashboard works at 375px width (stacked layout), 768px (2-col), 1280px+ (full)
- **Scalability**: Stateless API servers behind a load balancer; Redis for caching hot data
- **Security**: Input sanitization, rate limiting on upload endpoints, role-based access control
- **Error handling**: All API errors return structured `{ error, code, message }` JSON; UI shows inline error states, not blank screens
- **Offline resilience**: Frontend caches last-known state in IndexedDB; shows "Last updated X mins ago" when disconnected
- **Data integrity**: All uploads are idempotent; duplicate detection by unique constituency+candidate+election key
- **Export**: Any table or chart can be exported as CSV or PNG

## 📌 ADDITIONAL NOTES FOR AI CODING TOOLS

- **Always use TypeScript strict mode** — no `any` types
- **All API responses follow this envelope**: `{ data: T, meta: { page, total }, error: null }`
- **All dates stored as UTC ISO 8601** in DB; formatted in user's timezone on frontend
- **Vote percentages calculated on frontend** from raw vote counts for consistency
- **Color for parties stored in DB** as `#hex` — applied dynamically in charts
- **CSV column names are user-mapped**, not assumed — always show mapping wizard
- **Never expose DB primary keys in URLs** — use UUIDs (uuid v4)
- **Rate limit upload endpoint**: max 10 uploads/minute per user
- **Max upload file size**: 50MB; reject gracefully with descriptive error
- **Charts must be accessible**: include aria-labels, data tables as fallback for screen readers
- **Use optimistic UI** for alert rule creation — show rule immediately, rollback on error
